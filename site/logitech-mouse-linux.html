Configure a Logitech gaming mouse on Linux: DPI, buttons and lighting

PeriHub sets DPI, buttons and lighting on supported Logitech G mice on Linux and saves them in the mouse. Here is what works today, and how it differs from Solaar and Piper.

The Windows installer is not code-signed yet. If SmartScreen blocks it, click More info, then Run anyway. Quit the maker's app and turn off its autostart before you open PeriHub: two apps talking to the same device get in each other's way.

What it looks like

The same window on Windows and on Linux.

The problem

The mouse works, its settings do not

On Linux a Logitech mouse moves the pointer straight away. Changing its DPI steps, remapping the side buttons or choosing a light colour needs a tool that talks to the mouse's own settings, and Logitech's G HUB has no Linux version.

Where PeriHub comes from

It was started by a G502 HERO owner who moved their gaming PC to Linux. The same app runs on Windows, and settings saved in the mouse follow it to any PC.

How it works on Linux

Install

A .deb (Debian, Ubuntu), an .rpm (Fedora, openSUSE), a Flatpak, an AppImage, or the perihub-bin package built from the repository on Arch and CachyOS.

USB access

The .deb and .rpm install a udev rule. With the AppImage or Flatpak you add it by hand. It covers only the devices PeriHub knows, and only for the user at the screen.

Change settings

Pick a profile, then change DPI, buttons and lighting. DPI and lighting are previewed live; nothing is written until you press Save to mouse, and a backup is kept.

App profiles

The mouse profile can follow the game in focus, on Hyprland, KDE Plasma and GNOME. Other Linux desktops are not covered yet.

On the G502 HERO that means up to 5 DPI levels from 100 to 25600, polling rate up to 1000 Hz, 11 buttons plus G-Shift, macros, and the logo and DPI indicator lights. The G300 keeps three profiles with 8 light colours, report rate and 4 DPI levels (confirmed on Windows so far).

PeriHub, Solaar and Piper

Solaar

A Linux manager for many Logitech keyboards and mice on Unifying, Bolt, Lightspeed or Nano receivers, and many on USB or Bluetooth. Its own README lists pairing, device settings, custom buttons and rules. See Solaar.

Piper

A GTK app for gaming mice that is a frontend to the ratbagd service from libratbag, so its device list is libratbag's, which per its README covers devices from Logitech, Etekcity, GSkill, Roccat and SteelSeries. See Piper.

PeriHub

One app for Windows and Linux and for several brands. Three Logitech mice are tested on real hardware; the rest depend on the memory format they report. Writes are backed up and read back.

These are different tools, not rivals. Solaar is built for receivers and pairing; PeriHub never sends a receiver's pairing commands. PeriHub also builds on libratbag's published documentation of Logitech's protocol, and credits it in its README. We have not compared the three feature by feature, so check each project's own pages for your exact mouse.

Which Logitech mice

Supported: tested on real hardware

  • G502 HERO
  • G502 X Wireless
  • G300

On Linux the G502 HERO is tested. The G502 X Wireless and the G300 were confirmed by users on Windows; nobody has saved to either on Linux yet. A G502 X Wireless read on Linux had a newer firmware whose memory format PeriHub cannot write yet, so it stays read-only.

Depends on the mouse: 28 more G mice

  • G Pro
  • G403
  • G703
  • G903
  • G305
  • G604

Support follows the memory format each mouse reports. The G604 over Bluetooth is read only; use its LIGHTSPEED receiver to change it. Unifying receivers need an optional udev rule on Linux, because what you type on keyboards paired to them uses the same interface; Solaar's own rule already opens it.

Questions

Is there a Logitech G HUB for Linux?

No. Neither G HUB nor SteelSeries GG exists on Linux, which is why PeriHub was written for both Windows and Linux.

Does PeriHub have to keep running?

Not for settings saved in the mouse: profiles, DPI, buttons and macros keep working with PeriHub closed. Software macros and app profiles need it running, and so does re-applying the DPI of receiver devices that have no onboard memory.

It says permission denied. What now?

With the AppImage or Flatpak, install the udev rule by hand: the command is in the USB permissions section of the README. The .deb, .rpm and Arch packages do it for you.

Can I run it next to Solaar or Piper?

PeriHub shows a warning when Solaar or logiops runs, because they may undo its DPI changes on receiver devices. Its README does not cover Piper, so use one tool at a time on a given mouse.
